# 提案：验证升级后动态质量循环

## 为什么要改

提案 45 已实现动态质量循环，但源码测试不能证明用户 `PATH` 中的真实安装版已经升级。默认配置还需要显式表达动态 `audit_N`、`targeted_repair_N` 与独立 QA 合同，避免安装验证只能依赖内部实现推断。

## 做什么

- 使用真实安装版 `oz flow config` 在隔离的临时 Git 仓库生成默认配置。
- 验证默认配置不包含 `max_repair_iterations`，并显式包含动态阶段与独立 QA 提示。
- 记录安装路径、版本及合同结果到本地运行证据。

## 非目标

- 不修改提案 45 已归档的动态调度实现。
- 不评测模型发现问题的准确率或性能。
- 不提交 `test-results/` 运行产物。

## 影响范围

- 默认 repair 提示模板中的动态阶段说明。
- 当前 change 的安装版合同测试与本地运行证据。
