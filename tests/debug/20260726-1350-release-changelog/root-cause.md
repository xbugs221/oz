# GitHub Release 更新日志同步

## 场景

- 仓库从 `v1.0.0` 起存在连续版本标签，但没有面向用户的统一更新日志。
- GitHub Release 创建时使用空说明，历史版本变化无法自动进入发布页。

## 证据

- `v1.0.0`～`v1.1.9` 共 13 个标签，变化散落在相邻标签的提交记录中。
- 初版提取脚本只匹配无日期标题，读取 `[v1.1.9] - 2026-07-24` 时错误回退到“尚未发布”。

## 根因与置信度

- 高置信度：发布流水线没有版本日志来源，也没有按标签提取 Release 正文的步骤。
- 高置信度：版本章节采用常见的“标签 + 日期”格式，而提取条件错误要求整行完全等于标签标题。

## 修复方案

- 根据标签历史建立面向用户的 `CHANGELOG.md`。
- 提供统一提取脚本，同时支持带日期和不带日期的版本标题，并在缺少当前标签时回退“尚未发布”。
- CI 校验发布说明可提取；Release 使用提取结果更新正文，并上传完整更新日志。

## 回归测试

- `bash tests/specs/release-automation/test_monorepo_cli_release_contract.sh`：通过。
- 精确提取 `v1.1.9`：通过。
- 不存在的未来标签回退“尚未发布”：通过。

## 剩余风险

维护者仍需在发布前更新“尚未发布”内容，或建立与新标签同名的章节，才能保证每个版本说明准确。
