# 优化首次完成后过早进入 QA

## 现象

`repair_1` 产出 `clean` 后，状态机立即进入 `qa_1`，没有要求优化智能体重新审查完整实现。

## 根因

原状态机把单次 `clean` 同时当作“优化者认为完成”和“优化结论已确认”，缺少独立的待确认状态。持续会话能快速修补自己发现的问题，因此单次自判容易过于乐观。

## 修复

增加可持久化的 `repair_confirmation_pending` 状态。首次 `clean` 只进入下一轮强制重审；确认轮仍为 `clean` 才进入 QA。确认轮发现问题会清除待确认状态，后续再次 `clean` 时重新触发确认。轮次耗尽但尚未确认时阻塞。

## 验证

- 状态机回归覆盖首次 `clean`、确认 `clean`、确认发现问题和末轮缺少确认。
- 集成回归验证 repair 会话复用、确认提示重新读取事实源、QA 会话隔离。
- 长期合同验证状态字段、提示词和真实工作流结果。

## 剩余风险

重审仍由同一模型和会话执行，不能消除共同盲区；独立 QA 继续承担最终放行检查。
