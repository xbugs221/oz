# 自查轮次上限修复记录

## 根因

`quality-loop-v1` 的 `audit_N` 只依赖 `needs_more` 和进展指纹收敛，没有独立轮次预算。只要每轮持续改变源码、测试或证据，就能不断创建下一轮自查。

## 修复

- 新增 `max_audit_iterations`，默认值为 3，设为 0 时保持不限轮次。
- 当前轮为 `clean` 时继续进入独立 QA。
- 当前轮为 `needs_more` 且达到上限时不再自查，直接进入独立 QA。
- 其他路径尝试创建超过上限的新 audit 时，在调用智能体前改为进入新的独立 QA。
- 旧 sealed run 缺少新字段时保留 0 值，不改变既有快照语义。

## 验证

- 配置解析覆盖默认值、显式 0、显式正整数和负数拒绝。
- 状态转移覆盖触顶 `needs_more`、触顶 `clean`、越界新 audit 和旧快照不限行为。
- 长期合同覆盖默认配置和 Mermaid 工作流图。
